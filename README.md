# سامانه یکپارچه تحلیل بازار — راهنمای فارسی

این پروژه یک برنامه وب محلی بر پایه **Python 3.12 + Django 5.2 + PostgreSQL 16** است. ZIP عمداً شامل پوشه `.venv`، رمزها یا کلید API نیست؛ محیط مجازی موجود شما باید در همان پوشه ریشه باقی بماند.

## ۱) ویژگی‌های پیاده‌سازی‌شده

- حساب کاربری، ورود/خروج، پروفایل و نقش‌های `USER`، `OPERATOR` و `ADMIN`.
- کنترل مجوز در سمت سرور؛ ثبت‌نام عمومی همیشه کاربر عادی ایجاد می‌کند.
- مدیریت کاربران: مدیر می‌تواند حساب را فعال/غیرفعال کند و نقش اپراتور را اعطا یا لغو کند.
- مطالب تحلیلی: تیتر، خلاصه، متن، تصویر، نماد، جهت بازار، تایم‌فریم، پیش‌نویس/انتشار و نشان‌کردن.
- نمادهای نمونه: GOLD، XAUUSD، EURUSD، BTCUSD و NASDAQ.
- ورود CSV با اعتبارسنجی ستون‌ها، timestamp، ترتیب زمانی، OHLC، حجم، داده تکراری و گزارش نتیجه.
- کلید یکتای دیتابیس روی `symbol + timeframe + timestamp` برای جلوگیری از تکرار کندل.
- نمودار کندل‌استیک با انتخاب نماد و تایم‌فریم، حجم، میانگین متحرک، EMA، RSI، MACD و خطوط تقریبی حمایت/مقاومت.
- تحلیل هوش مصنوعی با افق ۲۴ ساعت یا یک هفته، خلاصه محدود داده‌های چندتایم‌فریمی، خروجی ساختاریافته و بازبینی پیش از انتشار.
- ثبت تاریخچه نسخه‌های تحلیل و ابزار ارزیابی پس از ۲۴ ساعت و یک هفته.
- ثبت رخدادهای تغییر‌دهنده سامانه بدون ذخیره محتوای فرم یا رمز عبور.
- هیچ سفارش یا معامله خودکاری ارسال نمی‌شود.

## ۳) آماده‌سازی روی ویندوز

### نکته مهم درباره پوشه `.venv` موجود شما

شما قبلاً محیط مجازی را در این مسیر ساخته‌اید:

`C:\Users\<نام‌کاربری>\MarketAnalysis\.venv`

فایل ZIP پوشه `.venv` را ندارد. بهترین روش این است که فایل‌های داخل ZIP را **در پوشه `MarketAnalysis` فعلی ادغام/استخراج کنید** و پوشه `.venv` فعلی را حذف یا جایگزین نکنید. در صورت استخراج در مسیر تازه، باید محیط مجازی تازه بسازید و requirements را نصب کنید.

### روش راه‌اندازی اولیه

۱. مطمئن شوید سرویس `postgresql-16` در وضعیت Running است.

۲. پوشه `MarketAnalysis` را در VS Code باز کنید. در ترمینال PowerShell باید مسیر ریشه پروژه و پیشوند `(.venv)` را ببینید. اگر محیط فعال نیست:

```powershell
.\.venv\Scripts\Activate.ps1
```

اگر PowerShell اجازه اجرای اسکریپت نداد، فقط برای همان نشست اجرا کنید و سپس فعال‌سازی را تکرار کنید:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```

در صورت پرسش تأیید، `Y` را وارد کنید. این تنظیم فقط برای همان نشست PowerShell است.

۳. برای اطمینان از نصب وابستگی‌ها:

```powershell
python -m pip check
```

اگر پیام `No broken requirements found.` نمایش داده شد، ادامه دهید. اگر بسته‌ای کم بود، در پوشه ریشه اجرا کنید:

```powershell
python -m pip install -r requirements.txt --index-url https://repo.huaweicloud.com/repository/pypi/simple --timeout 120 --retries 3 --only-binary=:all:
```

۴. اجرای راه‌اندازی اولیه (فقط یک بار):

```powershell
python setup_project.py
```

این اسکریپت رمز مدیر PostgreSQL با نام `postgres` را به‌صورت مخفی از شما می‌پرسد. سپس یک نقش جداگانه به نام `marketanalysis_app` و دیتابیس `marketanalysis_db` ایجاد می‌کند، یک رمز تصادفی برای کاربر برنامه تولید می‌کند، آن را فقط در `.env` ذخیره می‌کند، Migrationها را می‌سازد و اجرا می‌کند، نمادهای نمونه را اضافه می‌کند و در پایان ساخت حساب مدیر Django را از شما می‌خواهد.

**رمز PostgreSQL و رمز مدیر Django را در چت نفرستید.** فایل `.env` محرمانه است و داخل ZIP/مخزن Git قرار نمی‌گیرد.

> اگر قبلاً `.env` ساخته شده باشد، اسکریپت قبل از ادامه از شما می‌پرسد؛ برای حفظ تنظیمات فعلی، گزینه `Y` را انتخاب کنید.

## ۴) اجرای سامانه

پس از موفقیت راه‌اندازی اولیه، در ترمینال VS Code اجرا کنید:

```powershell
python manage.py runserver
```

یا فایل `runserver.bat` را اجرا کنید.

آدرس‌ها:

- صفحه اصلی: `http://127.0.0.1:8000/`
- ورود/ثبت‌نام: `/accounts/login/` و `/accounts/register/`
- داشبورد: `/dashboard/`
- پنل اپراتور: `/operator/`
- نمودارها: `/market/charts/`
- مطالب: `/articles/`
- تحلیل‌ها: `/analyses/`
- مدیریت Django: `/admin/`

برای توقف سرور در ترمینال `Ctrl + C` را بزنید.

## ۵) اعطای نقش اپراتور

با حساب مدیر وارد `/operator/users/` شوید یا از `/admin/` بخش Users را باز کنید. نقش کاربر موردنظر را روی «اپراتور» قرار دهید و حساب را فعال نگه دارید. نقش از فرم ثبت‌نام عمومی قابل انتخاب نیست؛ کنترل دسترسی در سمت سرور انجام می‌شود.

## ۶) ورود داده قیمت

از پنل اپراتور، گزینه «ورود داده CSV» را باز کنید. فایل باید UTF-8 و دارای سرستون‌های زیر باشد:

```csv
timestamp,open,high,low,close,tick_volume
2026-11-06T10:00:00+00:00,4000,4008,3997,4005,120
```

`timestamp` باید ISO-8601 باشد. برای هر نماد و تایم‌فریم، زمان‌ها باید صعودی باشند. فایل نمونه در `static/sample_candles.csv` قرار دارد. اگر داده‌ها به ترتیب زمانی نیستند، ابتدا آن‌ها را در نرم‌افزار مبدأ مرتب کنید.

## ۷) تنظیم API هوش مصنوعی

تحلیل AI بدون کلید API اجرا نمی‌شود. پس از راه‌اندازی اولیه، فایل `.env` را در ریشه پروژه با ویرایشگر محلی باز کنید و مقدار زیر را فقط روی رایانه خودتان قرار دهید:

```env
OPENAI_API_KEY=کلید_شخصی_شما
OPENAI_MODEL=gpt-5.4-mini
AI_REQUIRE_ADMIN_APPROVAL=True
```

سرور را متوقف و دوباره اجرا کنید. کلید API را در مرورگر، فایل‌های JavaScript، ZIP یا چت قرار ندهید. دسترسی به API و هزینه آن تابع حساب و اعتبار API شماست و از اشتراک ChatGPT جداست.

پروژه از Responses API کتابخانه رسمی OpenAI استفاده می‌کند. نام مدل در `.env` قابل تغییر است؛ مدلی را وارد کنید که در حساب API شما فعال باشد. راهنمای SDK: [مخزن رسمی openai-python](https://github.com/openai/openai-python).

## ۸) انتشار مطلب و تحلیل

- `ARTICLE_REQUIRE_ADMIN_APPROVAL=False`: اپراتور پس از ثبت مطلب می‌تواند آن را مستقیم منتشر کند (تنظیم پیش‌فرض راه‌اندازی).
- `ARTICLE_REQUIRE_ADMIN_APPROVAL=True`: مطالب در صف تأیید قرار می‌گیرند؛ مدیر می‌تواند از Django Admin آن‌ها را منتشر کند.
- `AI_REQUIRE_ADMIN_APPROVAL=True`: تحلیل AI پس از تولید در وضعیت «در انتظار بازبینی» باقی می‌ماند و فقط مدیر می‌تواند آن را منتشر کند (پیش‌فرض امن).
- برای انتشار مستقیم تحلیل توسط اپراتور، این مقدار را در `.env` روی `False` قرار دهید.

## ۹) ارزیابی تحلیل‌ها

پس از ورود کندل‌های جدید و گذشت افق زمانی، از ترمینال اجرا کنید:

```powershell
python manage.py evaluate_analyses
```

این فرمان ارزیابی مکانیکی تغییر قیمت نسبت به کندل مرجع را ثبت می‌کند. نتیجه آن معادل بک‌تست حرفه‌ای یا عملکرد قابل معامله نیست؛ هزینه، لغزش، اسپرد و کیفیت اجرای سفارش را مدل نمی‌کند.

## ۱۰) نکات فنی و محدودیت‌های نسخه اول

- نمودار از TradingView Lightweight Charts نسخه 4.2.2 از CDN استفاده می‌کند. ابتدا از `unpkg.com` و در صورت خطا از `cdn.jsdelivr.net` بارگذاری می‌شود. اگر هر دو دامنه مسدود باشند، داده API سرور سالم است اما نمودار در مرورگر لود نمی‌شود؛ در آن حالت باید فایل کتابخانه به‌صورت محلی در static قرار گیرد.
- این نسخه برای اجرای محلی و توسعه است؛ برای انتشار عمومی، HTTPS، تنظیم DEBUG=False، دامنه مجاز، سیاست پشتیبان‌گیری و سرور production لازم است.
- برای سبک ماندن سیستم ۸ گیگابایتی، Celery/Redis، Docker و مدل AI محلی در نسخه اول اضافه نشده‌اند. درخواست AI هم‌زمان و سنگین را محدود کنید.
- Telegram bot، پلن اشتراک پولی و اجرای معامله خودکار در نسخه اول فعال نیستند. معامله خودکار عمداً خارج از محدوده سامانه است.
- داده‌های قیمت خودکار از بروکر دریافت نمی‌شوند؛ در این نسخه باید با CSV وارد شوند.
- مقادیر حمایت/مقاومت نمودار نسخه اول، بیشینه/کمینه‌های اخیر بازه نمایش هستند و جایگزین تحلیل ساختار بازار حرفه‌ای نیستند.

## ۱۱) پشتیبان‌گیری

برای پشتیبان‌گیری از دیتابیس، از ابزار `pg_dump` نسخه PostgreSQL 16 استفاده کنید. فایل‌های تصویر نیز در پوشه `media/` هستند و باید جداگانه کپی شوند. فایل `.env` را در پشتیبان امن نگه دارید؛ آن را در اختیار دیگران قرار ندهید.
